### Added
- Multi-model endpoint mimo-v2.6-pro (2026-11-04): `PROVIDER_TEMPLATES` registers `xiaomi` (`https://api.xiaomimimo.com/v1`, OpenAI-compatible); `COMMON_MODELS` order is priority, and `LLM_2_*` does not take the first-request slot (`_get_llm_config` always reads `LLM_CONFIGS[0]`), so the existing deepseek batches keep their default model. The exact model id is all-lowercase `mimo-v2.6-pro`; its request-body shape matches `llm_client._openai_extra_body()`.
- Model-pinning switch `AITESTER_LLM_MODEL_FILTER` (single-variable prerequisite): `run_benchmark._get_api_for_task` round-robins endpoints by `task_index % len(_VALID_APIS)`, so with two providers configured the *model* varies together with the *task* and a model comparison is not identifiable. The filter is applied in `config._load_llm_configs` rather than at the batch layer, because `_get_llm_config` falls back to `LLM_CONFIGS[0]` off worker threads — filtering only the batch side would yield "nominally one model, actually mixed". A filter that matches nothing does not fall back to the full set (it fails loudly); `docs/env_budget.yaml` register 253 → 256.
- Prompt-language lock `tests/test_prompt_language_lock.py` (12 cases): covers every injection-point builder (spec sections / CFG and path sections / boundary triplets / compressed feedback / operation map / branch coverage / localized edit / mutation feedback / probe snapshot / localization section / graphrag / multi-candidate / failure KB / spec refine / mutation-operator descriptions) and asserts that text this project generates contains no CJK and no full-width punctuation. User item 13 becomes an executable lock instead of a one-time cleanup. Fixture data is ASCII, so any CJK hit must come from the scaffolding.
- LLM sweep stage in the full-run runner (cost-first calibration): one stage per "model × arm × dataset face", with scale set by the profile (one task per cell for smoke, faces run to completion for full). `--estimate-llm` prints both projections before any execution or directory creation; the per-task token cap comes from **measured need per thinking tier**: 120k when thinking is on (the 84k single-task maximum recorded in `llm_client`, plus headroom) and 20k when thinking is off (the current default; measured 709 output tokens for one call × the worst-case 4.3 calls/task ≈ 3.0k, with 6.6× headroom). It is **never derived by dividing the budget** — that would license each task to burn its own share — and the 120k figure is not reused, since it inflates the protective bound sixfold and would block the max-scale profile without evidence. Measured projection for the full profile (2 models × 5 arms × 50 quixbugs tasks = 500 tasks): protective upper bound ¥80, measured reference (output side only) ¥12.19, both inside the ¥300 ceiling.
- Three cost channels: ① a zero-cost pre-spend dataset gate (`main.py check-dataset`: a face that will not load can never yield a verdict); ② identity-keyed cache enabled with per-stage `AITESTER_CACHE_NAMESPACE` isolation (at `TEMPERATURE=0` a same-key replay is equivalent to a resend, so retries and re-runs cost nothing extra); ③ `--off-peak` moves the sweep into the provider's idle half-price window (parameters unchanged ⇒ measurement equivalent, bill roughly halved); `--resume-dir` reads `INCREMENTAL_RESULTS.jsonl` and skips completed tasks instead of paying twice.
- Cost-reduction candidate list (`docs/COST_MODEL.md/.en.md` §5): no full-file patch echo (`EDIT_INTENT_ENABLE`), a cap on Planner test-case count, the Generator's per-test docstring mandate, forced regeneration when the first suite is all-green (RT1's unresolved confound), and `FAULT_LOCALIZER_ENABLE`. All five change model behaviour or artifact shape, so under the single-variable rule (item 12) they are **registered, not enabled by default**, each with its expected effect and the measurement that must come first. One item deliberately left alone is recorded too: the second paid call on bad JSON / mismatched parametrize is already capped at one retry with a corrective hint, so it is resilience, not waste.

- CNY pricing channel `pricing.estimate_in_table_currency()`: returns `(amount, currency, source)` in the table's registered currency with no FX conversion; `estimate_usd` keeps its historical "USD only" contract. `entry_block_reason` implicitly admits the CNY baseline currency (one shared predicate instead of per-site edits).
- Full-run monitor `scripts/run_all_tests.py`: auto-detects local cores/memory with a **75% CPU cap**, `--lf` retry rounds (3 by default), sampling load/memory into `REPORT.json`, and now runs **two profiles in one invocation** (default `--spec both`): `smoke` = one item per face (one nodeid per pytest file — collect with `-qq` first, then sample; one task per "model × arm × dataset face" for the LLM faces; the fast gate checks) verifying assembly only; `full` = maximum scale (`make test-cov` full suite plus coverage → `make gates` whole chain → LLM faces run to completion, i.e. no `-n` unless `--llm-tasks` is given).
- The smoke precondition is a judgement, not advice: `full` only accepts a passing `SMOKE_GATE.json` whose **configuration fingerprint** matches — the fingerprint covers the matrix shape and protocol values plus `HEAD` and a `git status --porcelain` digest (any edited file invalidates old evidence; `--jobs`/`--out` stay out, otherwise every new output directory would demand a fresh smoke run). On mismatch it refuses, printing the command to run and the expected fingerprint; `--allow-stale-smoke` overrides explicitly. Measured: the `--no-llm` smoke run passed 3 stages over 549 sampled cases, and the full profile exited `rc=1` without matching evidence.
- Both profiles now cover **the same set of faces**, differing only in one item per face versus all of them (user clarification): the smoke profile runs every non-`test` target of the gate chain — the list is read live from the Makefile `gates:` prerequisites, so it follows any gate added or removed — measured at 28 stages in 3.1 minutes (one of them, `dependency-audit`, alone 143 s); the dataset default became `all`, and the full profile runs each face to completion (no `-n` unless `--llm-tasks` is given).
- Three anti-fake guards on the face list: ① an unregistered face name is **refused** instead of degraded — `load_dataset` hands back the 3-example built-in face for unknown names (a documented graceful-degradation contract), so a typo would quietly "run every face" as three fake tasks; ② faces are deduplicated by data identity (task count plus first/last task id), naming each alias and each sibling face whose data directory is unconfigured, so one batch of data is never paid for twice; ③ faces with no data on disk (here `d4j_py`/`defects4j_python`, 0 items) are dropped with disclosure, and only an all-unreadable request refuses the whole sweep. After dedupe the measured independent faces are bugsinpy 8 + quixbugs 50 + swebench 225 + testgeneval 160 + ult 200 = 643 tasks per model×arm, i.e. **6,430 task-runs** at 2 models × 5 arms (protective bound ¥1,028.8, measured reference ¥156.8 ⇒ above the ¥300 ceiling it refuses and reports the largest affordable plan, ≤1,875 tasks).
- Unattended layer: `RUNNING.lock` (a live lock blocks a concurrent run; a dead pid is taken over — the missing piece among the three guards added after the 2026-11-02 queue-runaway incident), `PROGRESS.json` (atomically rewritten every tick: stage index and total, done-of-total, ETA, overall percent, silent seconds, cumulative stalls) and `DONE.json` (terminal rc plus pass/fail counts, written as the lock is released); run-level caps `--max-wall-hours` (default 12) and `--max-stalls` (default 6), which **stop opening new stages** and record a named failed stage (`aborted_wall_clock` / `aborted_stall_budget`) so a silently shortened run cannot read as a complete one.

- Progress and stall monitoring (shared by both profiles): each stage prints `progress% (done/total) | elapsed | silent seconds | load/core | mem | last line` every `--heartbeat`; totals come from `collected N items` / `workers [N items]` / run_benchmark's `待运行任务数: N`, and LLM completion counts read `INCREMENTAL_RESULTS.jsonl`. Silence beyond `--stall-after` (default 600 s) or the wall-clock cap terminates the **whole process group** (SIGTERM→SIGKILL) and counts as one failed attempt.
- Per-run temp root in the full-run monitor (2026-11-04): `stage_base_env()` builds `<report dir>/tmp` in one place, points `TMPDIR`/`TEMP`/`TMP` at it and reclaims it when the run ends, so one run's verdicts are no longer slowed by directories a previous run left behind; `build_parser()` was lifted out of `main()` so the locks can take arguments directly.
