## 1. 估算错误与修正

- **原估算**：`8,755,871 tok × (0.76×$0.3/M + 0.24×$1.2/M) ≈ $4.5`——假设 input 占 76%。
- **实测参照**：R-P0-2 三批 arm 级 `token_metrics` 的 input/output 拆分是
  **input 22% / output 78%**（如 seed42 aitester：input 565,287 / output 1,979,328；LLM 输出主导：
  Planner 规约 JSON + 生成测试 + 调试/补丁文本 + JSON 输出模式的 reasoning token）。
- **修正后上界估算**：`8,755,871 × (0.22×$0.3/M + 0.78×$1.2/M) ≈ **$8.8**`（官方价目表峰时全额口径；
  实际成本以本批 `token_metrics` 逐批实算为准）。
- **处置**：**不中止**。理由：① 用户已明确本次 LLM 配额充足并授权测试；② 单任务护栏
  `COST_BUDGET_USD=1.0` / `COST_BUDGET_TOKENS=200000` 远高于实测单任务最大（96,479 tok ≈ $0.09），
  失控风险未变；③ §2"成本失控（估算超 $6）→ 中止"指的是**跑前估算**触发，本批跑前估算（错误的 $4.5）
  未触发，属估算口径缺陷而非失控。该规则不追溯修改，事实如实披露。
- **教训（登记）**：跑前成本估算不得用"统一 input share"假设；应从历史批次 `token_metrics`
  的 input/output 实算份额推导（本项目 output 单价 4× input，份额误设直接导致 2× 低估）。
