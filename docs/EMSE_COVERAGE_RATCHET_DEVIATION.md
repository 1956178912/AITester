## 2. 偏差归因（已核验与未核验的部分）

| 假设 | 核验结果 |
|---|---|
| 本地环境缺 CI 凭据变量导致用例未运行 | **已排除**：加 `LLM_1_API_KEY/BASE_URL/MODEL_NAME` 后重测，行覆盖仅由 92.07% 升至 92.10%、分支 86.21%→86.27%，无法解释 0.30/0.63pp |
| 本地依赖比 CI 少导致模块导入失败 | **已排除**：CI 装 `requirements.lock`（132 项全量钉版），本机同一 lock；`check_branch_coverage` 的核心模块分支覆盖为 0 的问题在加 CI 环境变量后解除（该门禁自始通过） |
| 新增源码未被测试覆盖 | **部分成立**：新增 `src/budget/batch_quota.py`（≈63 行，专项 18 例测试，覆盖充分） |
| 缺口是"不可测的死代码" | **已否证**：连续 16 批定向补测把行覆盖从 92.07% 推到 **92.54%**、分支从 86.21% 推到 **86.90%**——缺口全部是可测的真实分支（详见 §0.1 轨迹） |
| 水位登记时的分母与本次不可比 | **仍未核验（不再阻塞）**：水位登记处记录的分母为 15411 语句，本次实测分母为 16691 语句 / 131 文件。该差异可能意味着"部分 gap 是测量基准变化"；但因偏差已通过补测消除，此项转为**历史备注**，不触发水位调整 |
