# 「已在本进程之外验证」的路径登记（`scripts/tools/audit_fix_coverage.py`）
#
# 语义：本表登记**不需要在本进程内被执行**就能确认契约成立的新增行。它们从
#       「修复新增但从未被测试执行」的缺口清单里剔除，改列为「已在本进程之外验证」。
#
# 为什么要这张表：审计工具的判决面是**父进程**的 `coverage.xml`，而**子进程**
#       里跑的测试对它不可见——ED 轮那批「可选依赖装上但坏了」的负控制正是
#       在子进程里把目标包变成 RuntimeError 后验证降级契约的（见
#       `tests/test_optional_backend_broken_ed.py`）。本表把这类路径逐条登记，
#       否则工具会把**已验证**的路径报成缺口（实测：4 个文件 9 行），
#       而这正是该工具「长期无人跑」的主因——判决不可信 ⇒ 无人看。
#
# 语法：`<路径>:<行号> @<内容锚点>  # <理由>`
#   - 路径相对仓库根；
#   - 锚点 = 该行内容的唯一片段（**不用行号当键**：行号会随上方插行漂移）；
#   - 理由必须写——「没时间」不是理由；
#   - 锚点内容在该文件里消失 ⇒ 登记**失效**，审计以 rc=1 判红并要求重新判定
#     （内容改了 = 契约可能变了，必须重新确认，不能靠旧登记蒙混）。
#
# 本表为空 = 没有需要靠「进程外验证」兜底的路径。
#
