# 1. 引言

## 1.1 研究背景

软件测试是软件工程的核心环节，直接决定软件产品的质量与可靠性。传统手工测试依赖测试工程师的经验与时间投入，成本高昂且覆盖率有限。随着大语言模型（Large Language Model, LLM）在代码理解与生成任务上取得显著进展，自动化测试生成逐渐成为研究热点。

现有基于 LLM 的测试生成方法主要面临两大挑战：其一，**规划缺失**。单次 LLM 调用难以系统性地覆盖函数的全部逻辑分支与边界条件，生成的测试用例往往缺乏逻辑依据，导致覆盖率不足。其二，**修复能力有限**。测试失败后，现有方法缺乏系统化的诊断与自修复机制，需要人工干预才能继续推进。

## 1.2 研究问题

本文聚焦以下三个核心研究问题：

1. **如何系统性地引导 LLM 生成高质量的单元测试？** 即如何通过对被测函数的显式逻辑分析，引导 LLM 生成逻辑覆盖完整的测试用例。
2. **如何在测试失败后实现高效、可追溯的代码修复？** 即如何分类错误类型并应用差异化修复策略，以最小化 LLM 调用成本。
3. **多智能体协作相比单智能体或无规划方案，在真实缺陷数据集上的提升是否显著？** 即需要通过严格的消融实验与统计检验量化各组件的贡献。

## 1.3 核心贡献

本文提出 **AITester**，一个基于多智能体协作的 Python 自动化测试生成与自修复系统。主要贡献如下：

1. **逻辑驱动思维链（Logic-driven Chain-of-Thought）**：Planner 智能体在对被测函数进行显式逻辑分析（输入域、输出域、前置/后置条件、边界情况）后，再引导 Generator 智能体生成测试，显著提升测试用例的逻辑覆盖率与正确性。
2. **分层错误修复协议（Hierarchical Repair Protocol）**：将测试失败分为五类（SYNTAX / RUNTIME / ASSERTION / TIMEOUT / UNKNOWN），每类对应差异化修复策略；错误分类器采用 $O(1)$ 规则匹配，避免冗余 LLM 调用，大幅降低计算成本。
3. **可消融的多智能体协作框架**：通过布尔开关支持四种实验变体（完整系统 / 无 Planner / 无 Debugger / 纯 LLM），精确量化各组件贡献，实验设计透明可复现。
4. **标准数据集验证与统计检验**：在合成数据集（187 个任务）上验证方法有效性，并通过配对 t 检验与 Mann-Whitney U 检验证明 AITester 相对于基线方法的统计显著性。
