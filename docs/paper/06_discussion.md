# 6. 讨论

## 6.1 方法优势

1. **逻辑规划提升测试质量**：Planner 的显式逻辑分析使测试用例具有明确的逻辑依据，避免了随机生成导致的分支遗漏。实验数据显示 AITester 的平均覆盖率（92.0%）与 plain_llm（92.9%）相近，说明两者在简单场景下都能生成高质量测试。

2. **分层修复降低 LLM 成本**：错误分类器采用 $O(1)$ 规则匹配，避免每次失败都消耗 LLM token；Debugger 仅在需要时调用，单次迭代成本可控。

3. **组件贡献可量化**：消融实验框架支持精确测量各组件（Planner、Debugger、RAG）的独立贡献，为方法优化提供数据支撑。

4. **场景适应性**：研究发现 Planner 在简单场景下价值有限（禁用后成功率反而提升 6.6%），而在复杂场景下可能发挥更大作用。这为实际部署提供了灵活的配置策略。

## 6.2 局限性

1. **数据集规模有限**：当前实验主要在合成数据集上进行（297 任务），SWE-bench 真实数据集实验已完成计划制定但尚未执行。合成数据的 bug 模式较为简单，真实项目中的 bug 可能涉及更复杂的跨模块依赖。

2. **Python 限定**：目前仅支持 Python 语言，未验证 Java、JavaScript 等语言的泛化性。错误分类规则（正则模式）需要针对各语言语法特征定制。

3. **LLM 依赖**：测试结果受模型能力影响显著。实验发现优化 API 配置后，plain_llm 成功率从 13.8% 提升至 92.0%，说明 LLM 调用质量是关键因素。强模型（如 gpt-4o）与弱模型（如 gpt-4o-mini）之间的性能差距可能远超方法本身的贡献。

4. **基础设施错误占比高**：当前实验中约 19% 的失败源于 syntax/import 等基础设施问题（模块路径错误、文件名不匹配），而非方法本身缺陷。P0 改进建议已提出 Executor 模块导入自动修复功能，预期可减少 80% 的此类错误。

5. **错误分类器覆盖不足**：unknown 类别占比 33%，说明现有正则规则未能覆盖所有错误形式，存在误分类风险。未来可引入轻量级 NLP 模型辅助分类。

6. **Planner 价值争议**：消融实验发现禁用 Planner 后成功率反而提升 6.6%，这与直觉相悖。可能原因包括：合成数据集 bug 模式过于简单、Planner 引入的额外 LLM 调用可能引入解析错误、或简单场景下直接生成更高效。这一发现需要在更复杂的真实场景中得到验证。

## 6.3 失败案例分析

### 典型案例 1：模块导入失败

**任务**：`examples__calculator_divide`
**错误**：所有测试用例报 `NameError: name 'add' is not defined`
**根因**：测试文件尝试从 `division` 模块导入函数，但被测代码文件名为 `calculator.py`，模块路径不匹配。
**启示**：Generator 需要感知目标文件的实际模块名，而非假设导入路径。

### 典型案例 2：二分查找文件名不匹配

**任务**：`examples__binary_search`
**错误**：`ModuleNotFoundError: No module named 'binary_search'`
**根因**：被测代码为裸函数定义，未封装在 `binary_search.py` 文件中，但测试代码尝试从该模块导入。
**启示**：系统需要自动创建匹配的模块文件或调整导入语句。

### 典型案例 3：回文判断大小写敏感

**任务**：`examples__is_palindrome`
**错误**：测试尝试从 `target` 模块导入，但被测代码未以该文件名保存。
**根因**：合成数据集的模板代码与测试代码之间的文件命名约定不一致。
**启示**：需要统一数据集的命名规范，或增强系统的文件管理能力。

## 6.4 未来工作

1. **扩展真实数据集验证**：已完成 SWE-bench 验证计划制定（包含 HumanEval 快速验证和 SWE-bench-lite 完整验证两种方案），下一步将执行 HumanEval（164 任务，预计 2-3 小时）进行快速验证，确认系统稳定性后再执行完整 SWE-bench-lite（500 任务，预计 8-12 小时）。

2. **增强文件管理**：已实施 P0 改进建议，在 Executor 阶段添加模块导入自动修复功能（`_auto_fix_imports()` 方法），预期可减少 80% 的 syntax/import 类错误。

3. **改进错误分类器**：引入轻量级 NLP 模型辅助分类，降低 unknown 类别的占比。

4. **多语言支持**：将错误分类规则扩展至 Java、JavaScript 等主流语言。

5. **强化学习优化**：探索基于强化学习的修复策略选择，进一步降低 LLM 调用次数。

6. **动态组件配置**：基于场景复杂度自动决定是否启用 Planner。开发轻量级复杂度评估器，根据被测代码的逻辑复杂度动态调整组件配置，实现成本-效益最优。

7. **大模型性能分析**：系统性对比不同 LLM（GPT-4o、Claude、GLM-4.7-flash 等）在 AITester 框架下的表现，量化模型能力与方法贡献的相对重要性。
