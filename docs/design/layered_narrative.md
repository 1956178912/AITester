## 0. 一页结论（分层叙事地图）

EMSE 投稿的"规格优先 + 形式化规约"主张**必须按数据集分层**，三数据集
结论不可混述：

| 数据集 | 类型 | spec_compile_rate（新门） | detection 基线 | SpecExpr 增益 | 叙事定位 |
|---|---|---|---|---|---|
| QuixBugs（n=50） | 真实基准 | **0.7161**（旧门 0.6321） | ~63%（首轮即红 49/50） | pilot 阳性趋势未复现：A/B δ=−8.57pp/p=0.4531；C/D δ=−14.29pp/p=0.1797；合并 δ=−11.43pp/p=0.0768（批次五/八）→ **not_confirmed** | 主张成立的**主证据**（带功效限定语）；Mut@k 健全子集 **0.9396** |

| synthetic（n=174） | 合成模板 | **0.6397**（旧门 0.3102） | ~3%（无 flip 空间） | **阴性（信息性真阴性）** δ=−0.57pp / p=1.0 | **天花板反例**——证明增益需"差一步就检出"基数 |

## 1. 分层结论 1：detection 基线天花板（§6.7 主机制）

**事实**：
- QuixBugs 干净口径 detection 基线 ~63%（首轮即红 49/50）→ 有 ~37%
  flip 空间（0→1 检出）；
- synthetic 干净口径 detection 基线 ~3%（6/174 vs 5/174）→ 几乎无
  flip 空间；
- ULT 生成测试 detection 0/24 → 零基线（MCNemar 无判别力）。

**推论**（设计敏感性，预注册 61a7e04）：synthetic 上 +12pp 效应
（QuixBugs 量级）预期不一致对 ≈25，实测仅 3 → **阴性非功效失败，
是信息性真阴性**（基线天花板所致，非 SpecExpr 无效）。

**论文措辞纪律**：SpecExpr 增益主张**必须带数据集限定语**
（"在有可观 detection 基线的数据集上"），不得笼统表述为
"SpecExpr 普遍有效"。

**口径桥接（2026-10-17 独立评审 A-09 补入，强制阅读）**：
上文"~63% 首轮基线"与 E4 修正结算的 F2P detection **45.9%（17/37）**
不是同一口径，同句出现即误导：

| 口径 | 定义 | QuixBugs 值 | 用途 |
|---|---|---|---|
| 首轮即红率（red_seen） | 第一轮生成测试在 buggy 代码上出现红（含过红） | 49/50（~98% 首轮出红；63% 为其中特异红占比的估计口径） | 说明"缺陷可被触发"的上界 |
| F2P detection（三段判定） | buggy 红 ∧ fixed 绿 ∧ 无收集错误，None fail-closed 不进分母 | aitester 17/37=45.9%；plain_llm_df 31/37=83.8%（E4 FIXED harness，41 缺陷程序口径） | **唯一主指标**，一切对外对比以此为准 |

即：**~63% 描述 flip 空间存在性，45.9%/83.8% 才是跨臂可比的 detection**。
引用"~63%"必须同时给出上表，否则按误导性并列处理。

**跨批波动披露（A-09）**：同一 plain_llm_df 臂在 QuixBugs 41 口径上，
E4 FIXED harness（2026-10-09）为 83.8%（31/37），df_spec 对照臂
（2026-10-16 同批新跑）为 77.8%（28/36）——**跨批波动 6pp**（temp=0 下
的服务端非确定性/缓存差异，根因待澄清，见独立评审报告 §15 Q5）。
纪律：任何单批 QuixBugs detection 结论必须附此波动披露；功效解读以
n≈37 上 MDE≈16.1pp 为准，6pp 级差异不得表述为"趋势"。

## 2. 分层结论 2：可编译率度量假象（§6.9 勘误）

**事实**（§6.9 DSL 度量门修复后三数据集新门校准）：
- 旧门口径"数据集强分化"（QuixBugs 0.63 / ULT 0.56 / synthetic 0.31）
  主因 = **Planner 降级时签名提取静默失败**（function_name 为空或
  字面量 "unknown" → 回退默认参数集 {r,x,a,b,y} → 参数名/result
  子句被误判 unknown_name——合成集 270 次拒绝主源）；
- 修门后新门口径：QuixBugs **0.7161**（+8.4pp）/ ULT **0.5937**
  （+3.1pp）/ synthetic **0.6397**（+33pp）——上修幅度 ∝ Planner
  降级率（synthetic 降级率最高 → 上修最大）；
- 同任务新抽样 expr 覆盖率不变（0.693→0.686 / 0.748→0.707），
  而 unknown_name 拒绝崩塌（129→35 / 141→53）→ 分化是**度量侧**
  假象，非 DSL 表达力问题。

**推论**：BASELINE 已统一为新门口径（旧值留注释供审计）。对外引用
spec_compile_rate **必须带数据集标签 + 门口径标签**（新门 vs 旧门）。

## 3. 分层结论 3：变异敏感度、测试有效性与检出盲区（ULT/QuixBugs Mut@k，批次八修正）

> **本节 2026-10-15 批次八重写**：取代原「变异强但缺陷盲（ULT 维度洞察）」
> 一节。触发 = 全量 Mut@k 收口发现三项测量有效性缺陷（哨兵溢出 / 抽样
> 非确定性 / 健全性缺口）+ 一项上游数据问题（ULT gold 不一致）。历史
> 截断面数字（0.928 / 0.9543 / 1.0 / 0.9610）系统性偏高且不可复现，
> 不得再作对外口径。本节全变异体+健全子集定案值为唯一对外数字源。

**口径升级（批次八，取代截断面口径）**：

- **全变异体**：cosmic-ray 不设截断（哨兵值 10⁹；`ult_adapter` 整体超时
  改按实测条目数计算——修复前哨兵触发 PyTime_t 溢出，全变异体口径
  不可执行），`timeout=120s` 计 killed（ULT 官方，2026-10-13 裁定）；
- **健全性前置门**：套件须在目标代码上 30s 内**终止且通过**（rc=0），
  否则保守跳过（`test_nonterminating_on_fixed` / `test_fails_on_fixed`，
  不进 Mut@k 分母）。依据：① ULT 官方击杀判据 =「套件在变异代码上失败 ∧
  **在原代码上通过**」，且官方 `correct_tasks` 过滤（Ray/main.py 一手核对）
  就是"套件在未变异代码上 green"——本门即官方程序的**操作化**，非自创；
  ② 变异测试标准有效性前提：已红/挂死套件的击杀为恒红/超时驱动的平凡信号；
- **健全子集**：通过门的任务集；未过门任务全额披露（含分类与失败摘要，
  工件 `experiments/results/emse_test_sanity_20261015/`）。

**全量定案值（健全子集，零 LLM 逐位可复算）**：

| 组 | 目标代码 | n（健全/全部） | 全变异体 Mut@k | 截断·健全（对照） | 截断·全部（历史，单次随机抽样） |
|---|---|---|---|---|---|
| QuixBugs 生成测试 | QuixBugs fixed | 29/50† | **0.9396（1182/1258）** | 0.9323 | 0.9610 |
| ULT replace 生成测试 | ULT FUT（code 字段） | 9/46 | **0.6749（1590/2356）** | 0.7444 | 0.9543 |
| ULT specir 生成测试 | ULT FUT（probe25） | 5/25 | **0.4395（847/1927）** | 0.64 | 0.928 |
| ULT gold（上界参照） | ULT FUT（probe25） | **0/25** | —（全跳过） | 1.0（伪影） | 1.0（伪影） |

† 30 任务过健全门，其中 `node` 无变异点（skip）；20 任务门槛除
（17 恒红断言失败 + 3 非终止）。工件：
`emse_quixbugs_mutk_full_20261015/` + `emse_ult_mutk_full_20261015/`。

**三项测量偏差勘误（批次八发现与修复）**：

1. **截断面 = 随机抽样（非确定性）**：`max_mutants=10` 按 `job_id` 序保留，
   而 `job_id` 是 cosmic-ray init 的 uuid4 随机串 ⇒ 保留的是等概率随机
   子集；实证：同任务复跑评估不同样本（gcd 9/10 vs 10/10；ULT 232/250
   vs 230/250）。**抽样偏差方向不可预知**：QuixBugs 截断略保守
   （0.9323 vs 0.9396，−0.7pp），ULT next_holiday 极端高估
   （0.40 → 0.087，920 全变异体）。历史值须带「单次随机抽样」标签。
2. **健全性缺口（平凡击杀抬高归档值）**：QuixBugs 20/50、ULT lite46
   37/46、probe25 20/25 的生成套件在目标代码上 fail/nonterminate——
   其"击杀"为恒红/超时驱动。修正链：replace 0.9543（全部）→ 0.7444
   （截断健全）→ **0.6749**（全量健全）；specir 0.928 → 0.64 → **0.4395**；
   QuixBugs 0.9610 → 0.9323 → **0.9396**。
3. **ULT gold 参照作废（上游数据）**：官方 `test_list` 在 **71/71** 任务上
   无法在 `fixed` 通过（已排除包装/物化因素：官方物化风格复测同败；
   `fixed` 与上游 `ULT_Lite.jsonl` 的 `code` 逐字节一致）⇒「fixed = ULT
   正确实现」假设不成立，归档 gold 上界 1.0 系恒红套件平凡击杀**伪影**；
   "距 gold 4–8pp"作废，改以官方 published 基线（12 模型 Mut@k 均值
   **40.21%**，correct_tasks 口径）作**量级对照**（描述性，非严格同集
   比较——本项目修正后量级 0.44–0.67 与其可比，修正前 0.92–0.95 异常偏高）。

**分层解读（论文措辞纪律修订）**：

- **QuixBugs（主证据）**：健全子集全量 **0.9396**——"高变异敏感度"主张
  在修正口径下成立（主证据地位保持）；detection 基线 ~63% 且 M4 四臂
  （A/B/C/D）全部 not_confirmed（见 §6）——「规格优先无稳健增益」与
  「高敏感度、低检出」两结论并存；
- **ULT（降格）**：健全子集 0.4395–0.6749（有效子集内敏感度中等），
  叠加 ~80% 套件不满足有效性前提 + gold 参照作废 ⇒ ULT 侧改为三段式
  陈述：「**有效性缺口主导 + 有效子集内敏感度中等 + 检出盲（0 检出）**」；
- 「变异强但缺陷盲」的对外表述**必须带健全子集限定语**，ULT 侧按新值
  引用，不得使用历史截断面值；
- **测试有效性缺口本身作为可报告现象**（对齐 ULT 官方 accuracy /
  `green_on_fut` 口径，**不与 detection 混用**，per ult_bridge_plan §3.2）：
  生成套件在目标代码上的有效性通过率 QuixBugs **60.0%**（30/50）、
  ULT lite46 **19.6%**（9/46）、probe25 **20.0%**（5/25，pooled 14/71）
  ——对照官方 12 模型 accuracy 均值 **41.32%**（量级对照，非同集/同协议：
  本项目单次规格优先 + ULT_Lite 子集，官方 K=20 greedy + 全量 3909）；
  失败四分类：
  ① 相对导入收集错误（QuixBugs `*_test` 变体 9 例）；② 函数名不一致
  （ULT `_normalized_vcf` 类 4 例）；③ 断言失败/恒红（QuixBugs 8 +
  ULT 51，含上游不一致样本 time_in_swiss_german 拼写 "quartel" vs
  "viertel"）；④ 非终止（QuixBugs 3 + ULT 2）。

**方法论贡献（新增）**：mutation-score 报告的三个隐藏偏差源——① 随机
抽样截断面（uuid4 序；样本量小且偏差方向不可预知）；② 恒红/挂死套件的
平凡击杀；③ 分母不披露。报告规范建议：全变异体（或种子化确定性抽样）
+ 有效性前置门 + 健全子集分母 + 未过门清单披露；**gold 参照须先验证
gold 在目标代码上通过**（本批次 71/71 反例）。

**口径标签（跨报告引用纪律，强制）**：

- `全变异体`（cosmic-ray 不截断）vs `截断面`（历史 `max_mutants=10`；
  = uuid4 随机序单次抽样，非确定性——引用须带「单次随机抽样」标签）；
- `健全子集`（目标代码上终止且通过 30s 前置门）——本表 Mut@k 默认即此

- `timeout=120s`（timeout 计 killed，ULT 官方）；cosmic-ray 8.7.0 +
  配置哈希 `1e1230a7e298d1e2d7856ca437332e27702cfa1612dfc80ab71f9ca105b6ea22`；
- 与合成集自研 mutation score（0.955 饱和）**不可直接比**（算子集/超时/
  变异体数量均不同，双口径分述纪律不变）。

## 4. 分层结论 4：M10 解析层误诊的度量分层（§6.10，ADR-0031/0032）

**事实**（ADR-0031 LLM 结构化输出加固 + ADR-0032 M10 可观测性强化）：
- 此前 ~7-8% 任务（6/75）触发 M10 降级，其中**大部分实为解析层缺陷**
  而非 LLM 缺字段：①JSON 语法非法（LLM 写 `10**18` 类 Python 数值
  表达式）→ 叶子回退静默返回错误片段 → 误诊"LLM 未输出
  logic_analysis"；②结构化契约无运行时约束（未用 DeepSeek 官方
  JSON Output）；③finish_reason 截断/资源中断静默；
- ADR-0031 三项加固后冒烟 **M10=0**（修复前 1 例回退默认计划）；
- ADR-0032 补 M10 归因分层：`m10_leaf_fallback=True` 标记
  "提取器叶子回退误诊"（纯观测，分离"LLM 真未输出" vs "解析层缺陷"）。

**论文定位**：EMSE 报告 §6.10 须披露**评测可靠性边界**——2026-10-14
之前批次含 ~7-8% 解析层误诊降级（logic_degraded 统计偏保守），
"逻辑驱动"路径实际覆盖率比历史记录更高；对外引用 M10 率
**必须带"误诊已分层"限定语**（ADR-0032 后新批次可分离计数）。

## 6. M4 预注册：QuixBugs specir 扩样确认性实验

> 预注册件：`docs/study/QUIXBUGS_SPECIR_EXPAND_PREREG_2026-10-14.md`
> （gitignored，本地件，**结果产出前落盘**——EMSE Registered Reports 机制）。

**背景**：QuixBugs specir pilot 阳性趋势 δ=+14.29pp / p=0.125（n=35，
标准口径 6:1），功效不足需补样。temp=0 常驻（R11）⇒ 同任务重跑（缓存
命中）= 零信息；QuixBugs 本地即完整 Python 子集 50 程序（存量已用满）
→ 扩样路径 = **同任务 × 跨批次新抽样**（独立 cache namespace，跑批前
须验证命名空间互异，防跨臂缓存命中退化）；4 臂（每臂 n=50）：A/B（批次五）
+ C/D 复跑（批次八）。

**判定规则**（与 61a7e04 同族）：主分析 McNemar 配对（A vs B，n=35）+
复跑（C vs D）+ 合并（A∪C vs B∪D，n≤100）：p<0.05 ∧ δ≥8pp = confirmed /
p<0.10 ∧ δ>0 = trend / 其余 = not_confirmed。

**成本预算**：~$0.3（4 臂 × 50 任务；实际各臂 ~29 min）。

**批次八执行结果（2026-10-15，用户授权）**：C/D 复跑臂完成（1731s/1751s；

## 9. 分层结论 5：df_spec 实验——"替代码为规格锚"呈现显著负效应（P1 主实验，2026-10-17）

**事实**（预注册 `docs/study/DF_SPEC_PREREG_2026-10-16.md`，sha256
`a19a6c29…`（承诺哈希记录于跑批前入库提交 `cd514d2`）；判定口径
`experiments/emse_df_spec_analysis.py` 于结果产出前入库锁定）：

- **设计**：QuixBugs 双臂（`plain_llm_df_spec` vs `plain_llm_df`，单变量 =
  prompt 代码块替换为预计算规格锚），41 缺陷程序口径、同批同日、独立 cache
  namespace、logic 档 / temp=0；锚命中 **50/50**（`spec_replace_applied=
  attempted_replaced`，仪器无故障）；两臂 provenance `git_dirty=false`；
- **主终点：`not_confirmed`（方向为负的显著证据）**——df_spec
  **54.3%（19/35）vs** df **77.8%（28/36）**；配对 **1:10**、δ=**−25.7pp**、
  双向精确 p=**0.0117**、BF10=16.4（MDE 16.6pp）；预注册三条件
  （≥60% ∧ 单向 p<0.05 ∧ 误导 proxy −30%）**全未满足**；失败线（<50%）未触发；
- **机制侧（描述性）**：over_red 占比 **46.0% vs 22.5%**——预注册预期
  "下降 ≥30%"，实测**反向上升 104%**；specific_red 20 vs 31；

  E4 df 独有 11（方向一致、量级更强）；同批 df 对照为主配对（隔离模型版本/环境）；
- **工件**：`experiments/results/emse_df_spec_20261016/`（两臂批次 JSON +

**推论**（基于证据的机制假设，待独立预注册检验，不作定论）：

锚材料由 Planner 对**目标（缺陷）代码**的历史分析物化
（`build_spec_anchor_table` 自既有 LLM 缓存提取 `logic_analysis`）——
它是"对缺陷行为的再描述"，**不是独立于缺陷的正确规格**。据其生成测试
→ 更易断言缺陷行为（over_red↑）→ 特异检出↓——与实测方向一致。**本负结果
不读作对 Zhao et al.（ISSTA 2026）"spec-based prompting 缓解误导航"的
反证**（其设定使用独立 spec docstring），而读作一条**操作性警示**：
锚材料的来源必须是独立正确规格，而非对缺陷代码的再描述。

**定位纪律（对外引用强制）**：

1. P1 成功判定全未满足 → 论文主标题不升级（维持现版本）；

   扩样未确认 / 本实验显著负）均**未显示检测增益**——对外表述统一为
   "本系统内、以此实现方式"的路线级负证据，不得扩大为"规格锚定普遍无效"；
3. 引用本实验必须带隔离链标签（处理 = df + 锚替换；非 aitester spec_first
