# ADR-0018: 结构化编辑意图 + 确定性落盘——补丁产出从"整文件重写"转向"意图→确定性引擎"

- 日期：2026-10-07（修复引擎批次 III，第十六轮审查 R16-3 落地）
- 状态：已采纳（Accepted，`EDIT_INTENT_ENABLE` 默认关、灰度 A/B 后转正）
- 关联：ADR-0017（修复引擎三阶段）、ADR-0016（编排定位重述）、ADR-0003（默认关惯例）、`src/tools/patch_intent.py`、`src/agents/debugger.py`、`src/graph/nodes.py`

## 背景（Context）

E2 定案 + 修复上限归因表明 repair=0 的卡点在补丁质量（plausible 46.8% → correct 0），而补丁产出方式本身是前沿实证指出的结构性缺陷：

1. **diff 落盘不可靠（实证）**：arXiv:2609.00227 实测——严格 unified diff 无人值守几乎全失败，宽容工具约 **1/7 被静默错误应用**；Diff-XYZ（arXiv:2510.12487）证明 search/replace 格式优于自由 udiff。
2. **本仓现状**：debugger 产整文件替换 patch（E7 工作表实证带 LLM 格式伪影/无关注释）；`patch_applier` 的危险 API 守卫与命名契约守卫只做安全/签名校验，**无"应用结果与意图一致"的机制保证**。
3. **第二阶段路线（ADR-0017）**要求"确定性后处理 + 多 Hunk"——多 Hunk 编辑的前提是每处编辑可独立校验落盘，整文件重写做不到。

## 决策（Decision）

1. **LLM 产意图、确定性引擎落盘**：`EDIT_INTENT_ENABLE` 开启时，debugger prompt 要求响应 JSON 附加 `edit_intents` 字段：`[{"old_str": "<原文唯一锚点>", "new_str": "<替换>"}]`（多处修改按从上到下每处一条——多 Hunk 原生支持）。
2. **确定性应用规则**（`src/tools/patch_intent.py::apply_edit_intents`）：
   - 逐条锚点唯一性校验：old_str 在当前工作副本中**恰好出现一次**，否则整体拒绝；
   - 顺序应用（前一条结果为后一条工作副本）；
   - **原子性**：任一条拒绝 → 丢弃全部修改返回原码（调用方回落 legacy 整文件补丁通道，不产生半应用状态）；
   - AST 语法门：结果须可解析；原文本本就不可解析时豁免（存量语法错误不误杀编辑，由执行层自然暴露）。
3. **替换语义**：意图应用成功 → 用最小编辑结果替换整文件 patch（最小 diff 口径）；失败/无意图 → 原子回落历史通道。
4. **观测面**：`debug()` 返回 `edit_intent_status` → `state["edit_intent_status"]` → 结果行透出（开关关恒 None，键集合同构）；实验层据此统计意图通道接管率与拒绝原因分布。
5. **默认关（ADR-0003 惯例）**：A/B 对照（同任务集 × {意图通道, 整文件通道}）出数后再议转正；转正判据预注册前定为——接管率 >0 且意图臂 patch_correct 不低于对照臂。

## 后果（Consequences）

**正面**：静默错应用被机制性封堵（锚点不唯一即拒绝）；多 Hunk 编辑获得地基；最小 diff 降低 review/回滚成本；与 2.1 类型修复层（成功即替换 patch）同构，管线语义一致。

**负面/风险**：锚点精确性要求提高 LLM 遵循难度（格式重试已有 P0 4.1 通道兜底）；每任务新增意图解析（零 LLM 成本）；拒绝回落可能让意图通道在初期表现为"无增益"——须以接管率指标区分"通道不行"与"锚点太严"。
