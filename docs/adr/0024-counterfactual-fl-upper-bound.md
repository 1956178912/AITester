# ADR-0024: 反事实 FL 上界分析——存量归因分解 + 运行时 gold 注入臂

- 日期：2026-10-07（修复引擎批次 X，第十七轮审查建议 1）
- 状态：已采纳（Accepted——回放工具已出数；运行时臂默认关待跑批预算）
- 关联：ADR-0017（修复引擎——FL 瓶颈假设的**首测修正**见本文）、ADR-0021（修正 correct 口径使本分析可行）、`src/agents/fault_localizer.py`、`experiments/cf_upper_bound.py`

## 背景（Context）

1. 第十七轮审查建议 1（RGFL 反事实上界分析）：把修复失败严格分解为**定位侧瓶颈**与**生成侧瓶颈**，回答"如果 FL 给出正确位置，修复能否成功"——此前 correct 恒 0 无法归因，ADR-0021 修正后存量工件即可分解。
2. ADR-0021 的连锁修正：repair 从"0 → 破零"变为"38.7% → 提升"——优化预算应投向实测瓶颈，本分析正是瓶颈定位器。

## 决策（Decision）

1. **存量回放归因分解**（`experiments/cf_upper_bound.py`，零 LLM）：FL 口径（`localization_hit_function` 优先；存量批次 I 之前工件无该字段时回退谱系行级 `fl_at_1`）× 修正口径 correct（复用 `repair_replay` 判定）的 2×2 分解——a 双对 / b 生成侧瓶颈 / c 碰巧修对 / d 定位侧瓶颈；关键比率 **P(correct | FL 命中)** = "完美 FL 下修复率的存量代理"。
2. **运行时反事实臂**：`FL_GOLD_INJECTION_ENABLE`（默认关，ADR-0003）——`_debugger_node` 在开关开且 `state["gold_fixed_code"]` 存在时，定位段直接用 `build_gold_injection_localization()` 构造（gold 变更函数 → AST 行范围 → 同构候选，confidence=1.0，reasoning 自带"反事实臂"标注），**跳过 LLM 推理通道**；优先级高于 `FAULT_LOCALIZER_ENABLE`。臂间差分 = FL 的端到端贡献（严格上界）。
3. **卫生口径例外登记**：`state["gold_fixed_code"]` 本为门禁专用材料（AC2，"任何 agent prompt 不得引用"）——本开关是**显式消融例外**（注入的是 gold 函数名/位置，非修复内容），该臂数据不得与正常口径混读，结果行以 reasoning 标注可识别。

## 首测结论（2026-10-07，存量回放，E2 迭代双批 53 可分解行）

| 量 | 值 | 含义 |
|---|---|---|
| FL 命中率 | 35.85% | 与 FL@1 35.8% 一致（回退口径正确性自证） |
| **P(correct \| FL 命中)** | **15.79%**（3/19） | 给对位置（谱系口径）修复率反而最低 |
| P(correct \| FL 未命中) | 64.71%（22/34） | 定位未命中组的修复率反而高 4 倍 |
| 实测修正 repair | 47.17% | (a+c)/n |

**方向性发现（ADR-0017 的 FL 瓶颈假设首测修正）**：谱系 FL@1 命中与修复成功**负相关**——FL 命中组 84%（16/19）修不好（生成侧瓶颈主导）。合理解释：①当前补丁生成为**整文件重写**，对定位信号的消费本弱（ADR-0018 立项动机同源）；②谱系 Top-1 命中的多为覆盖深、暴露明显的复杂缺陷，未命中的含大量 import/语法类可确定性修复的简单缺陷——FL 命中率与缺陷难度混杂。

**含义**：提升修复率的杠杆排序修正为——(a) 补丁生成的定位消费方式（编辑意图局部编辑 > 整文件重写）＞ (b) FL 精度提升本身；(c) 严格验证须运行时臂（gold 注入 vs LLM 臂差分，LLM 函数级口径 + 解混杂），待跑批预算。

## 后果（Consequences）

**正面**：瓶颈归因首次可计算（零 LLM 回放）；运行时臂就绪；ADR-0017 的"局部化是第一短板"假设获得第一份反证数据，第二阶段优先级获得实证基础。

**负面/风险**：回退口径混合粒度（函数级 vs 行级）——fl_sources 分列披露但跨批对比须同口径；n=53 小样本；运行时臂消耗跑批预算且开启时不可与正常批次混读。
