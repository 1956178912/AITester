# ADR-0038: 冒烟证据的适用边界——并发决议、选面与协议取值同属一次配置

- **状态**：已采纳
- **日期**：2026-11-06（代码落地 2026-11-05，B12 + B8 两轮）
- **关联模块**：`scripts/run_all_tests.py`（`config_fingerprint:885`、`resolve_llm_parallel:256`、
  `machine_parallelism_cap:242`、`apply_concurrency_fingerprint:299`、`dataset_gate_verdict:1626`、
  `protocol_caliber_env:1613`）、`src/config/config_generator.py:54`（`MODEL_RATE_LIMITS`）
- **相关决策**：ADR-0003（默认关纪律）、ADR-0015（detection-first 协议）、ADR-0037（图内 gold 与口径同源）

## 1. 背景

两档运行器（`smoke` 每面一项验装配 / `full` 每面跑满出读数）已经要求 `full` 只认**同配置指纹**
且通过的冒烟证据。但 2026-11-05 的实测暴露两处"指纹没绑住的东西"：

1. **规模墙钟**：按实测 183 s/任务外推，满量档 1,464 任务 ≈ 74.6 小时，远超运行器 12 小时封顶。
   并发是这件事的**可行性前提**，而每格并发当时钉死在 `LLM_PARALLELISM_CAP=4`——一个与厂商额度
   无关的常数。更糟的是：如果冒烟在 4 并发下跑通、满量档在 40 并发下开跑，那么"验过装配"的
   证据覆盖的**不是将要付费的那个配置**（超发改变 429/超时分布，进而改变判定覆盖率）。
2. **闸不消费结果**：付费前的数据集闸只作为阶段铺在 LLM 段之前，**没有任何代码读它的退出码**
   ⇒ 被判不可判定的面照样进入付费段，而整轮 rc 只因它变红——冒烟证据因此不可用，full 档开不了跑。

## 2. 决策

**"一次配置"的边界扩大到会改变判定分布的三件事，全部进指纹；闸从"阶段"改为"选面输入"。**

1. 每格并发 = 逐模型决议：`厂商额度 × 80%` ∩ `机器闸` ∩ 显式 `--llm-parallel`
   （`resolve_llm_parallel`），决议结果 `apply_concurrency_fingerprint` 写入指纹。
   - 额度登记在 `MODEL_RATE_LIMITS`：`deepseek-flash` 在途 2500、`deepseek-v4-pro` 在途 500
     （语义"请求发出至响应完成计 1 并发"）、`mimo-v2.6-pro` **RPM 100 / TPM 10M**。
   - **两种量纲不可互换**：在途档直接当并发上限；RPM 档只封发起速率（80/min），并发由机器侧定。
   - 机器闸 = `min(核数 × 2.4, 内存项, 40)`，下限 2，采样失败取保守值——依据是冒烟心跳
     `load/core 0.27`、`mem 14.6/24 GB`：**时间花在等待本地测试子进程，不在 API**。
   - 显式 `--llm-parallel` 越额度时**封顶到额度并在 note 点名**（越线只会换来 429）。
2. `dataset_gate_verdict(face)` 的结果进入 `llm_scale_plan(gate=...)`：红面**剔除并点名披露**，
   剔除项进投影（`gate_dropped`）；闸不再是阶段 ⇒ 不再毒化整轮 rc。
3. 面计数、闸、实跑三处口径**同源**于 `protocol_caliber_env()`（含
   `AITESTER_DATASET_STRICT_INSTANCE_CODE` / `..._STRICT_TEST_CODE` /
   `PATCH_EVIDENCE_OFFICIAL_TESTS_ENABLE`）——不同源就会出现"闸判绿的面，实跑按另一口径付费"。
4. 不进指纹的取值保持不进：`--out` / `--jobs` 不改变"哪些面被覆盖"，否则换个输出目录就要重跑
   一份付费冒烟。`--estimate-llm` 保持纯算式、不跑闸 ⇒ 投影是**上界**而非承诺。

## 3. 后果

- 换并发、换面集、换协议取值、改任何文件——旧冒烟证据一律失效，必须重跑；这是把"证据的
  适用范围"写成机器判据，而不是靠人记得。
- 满量档的墙钟瓶颈从"常数 4"变成"额度与机器的交"，但**瓶颈本身仍在本地测试超时**（30/60/120s
  档），不在 API 侧：并发提升的是排队，不是单任务耗时。
- 不可判定的面在付费前就被剔除，且剔除理由逐个可见（不是静默缩规模）。

## 4. 已知局限与演进方向

- RPM 档目前只把额度换算成发起速率，`api_manager` 侧还**没有真正的按分钟令牌桶**（登记为残项）；
  在途档同理没有全局在途计数闸。现口径是"按决议值发起"，不是"按窗口硬限流"。
- 机器闸在启动时**一次采样**，不随负载回缩；长跑中途的内存压力变化不会重议并发。
- swebench 面在新口径下 217/225 可判，但冒烟 10 格仍全 `harness_invalid`（基线 P2P 不达标）——
  满量档是否保留该面是**规模决策**，不由本 ADR 判定。
