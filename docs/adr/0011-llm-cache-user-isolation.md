# ADR-0011: LLM 缓存用户隔离与创建者归属（2026-09-29 批次）

# 背景（外部数据支撑）

- **Clinejection 事件**：攻击者仅通过一个恶意 GitHub issue 标题，无需仓库
  访问权限，就对 Cline 的 AI 分类机器人实施 prompt injection，进而污染构建
  缓存，最终向 4,000 名开发者推送恶意 npm 版本。完整攻击链：
  "缓存投毒 → 跨工作流凭证窃取 → 恶意分发"。
- **KeyPooling 研究**：通过 OpenRouter API 网关架构，共享组织凭据的路由
  可能"无意中在所有用户之间创建全局缓存共享"，缓存式提示泄露比此前
  报告的威胁更严重。
- **KV 缓存与提示词缓存攻击研究**：两个请求共享缓存 KV 项时隐含信息
  通道；多租户服务环境中成本压力（缓存最大化共享）与安全（严格隔离）
  的张力形成持久攻击面。

本项目的 LLM 文件缓存（`src/cache/*.json`）此前假设"本地可信域"：
0o600 文件权限 + 0o700 目录权限（18. 批次）+ 0o700 目录（新建收敛），
但**共享 CI 环境 / 多用户机器**上，同一工作目录下的缓存目录可被同机
其他 CI 步骤 / 其他用户写入（0o700 只防同机跨用户读，不防同 uid 下的
跨 CI 步骤投毒，如 Clinejection 的跨工作流传递）。

# 决策

1. **缓存条目写入创建者标识**：`creator_uid` 字段写入每个缓存文件头部
   （POSIX uid 字符串；可通过 `AITESTER_CACHE_CREATOR` 环境变量显式覆盖，
   共享 CI / 多租户部署可为不同身份注入独立标签实现逻辑隔离）。
2. **读侧归属校验**：`cache_creator_ok()` 在文件命中校验链上追加
   创建者检查——条目 `creator_uid` 非空且与当前标签不一致时，该条目
   **不命中**（按投毒面处理，走真实 LLM 调用）；历史无该字段 / 空值
   条目视为兼容（不破坏既有 2,200+ 缓存文件）；标签为空（uid 不可得
   的平台）跳过校验（历史口径）。
3. **权限口径不变**：18. 批次的 0o700 目录 / 0o600 文件 + TTL 清理
   保留，作为第二层纵深防御。
4. **历史文件迁移**：不做批量改写（保守）——读侧兼容逻辑自动覆盖
   无字段条目；新写入条目一律带 `creator_uid`。

# 后果

- 正面：封堵"跨用户 / 跨 CI 步骤缓存投毒"攻击面（Clinejection 式
  投毒路径在本缓存层失效——被污染条目读侧拒绝应用）；多租户部署经
  `AITESTER_CACHE_CREATOR` 获得逻辑隔离。
- 负面：缓存文件头部多一个字段（字节开销 ~30B，2,200 文件 ~66KB，
  可忽略）；共享 CI 下同一 uid 的多工作流仍共享缓存（逻辑隔离需
  显式设置不同 `AITESTER_CACHE_CREATOR`）。
- 回归守卫：`tests/test_multiprocess_cache_consistency.py`
  （投毒模拟 + 负缓存过期重读 + 假阳性抽样统计）。
