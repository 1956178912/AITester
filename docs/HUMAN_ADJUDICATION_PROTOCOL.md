## 1. 目标与判定规则（预注册原文 + 已生效的修订注记）

### 2.2 样本量决策的统计依据（0 equivalent 观察下的真零上界）

E7 判定规则对"残余语义等价占比 > 0"敏感（触发 repair 口径勘误）。若某样本量下
观察到 **0 个 equivalent**，真实占比的 95% 上界（rule of three / Wilson）：

| 样本量 | 0 observed 上界（rule of 3） | 0 observed 上界（Wilson） | 1 observed 上界（Wilson） | 人工成本量级 |
|---|---|---|---|---|
| n=8（路径 A） | 37.5% | 32.4% | 47.1% | ~1 小时 |
| n=41（路径 B） | 7.3% | 8.6% | 12.6% | ~4-7 小时 |
| n=72（全框普查） | 4.2% | 5.1% | 7.5% | ~6-12 小时 |

**解读**：论文"repair=0 为真零"的论断强度直接取决于样本量——n=8 的 0 观察只能把
真实等价率压到 32% 以下（不足以支撑"真零"的定量表述）；n=41 压到 9% 以下，
n=72（取消抽样、全框普查）压到 5% 以下且**无抽样误差**。成本量级为 patch-vs-gold
逐行对照的估计（工作表已备齐全部素材）。**建议**：若论文需保留"真零"类定量表述，
至少走路径 B；工件包定稿（Zenodo）前可考虑全框普查作为最终工件。

**抽样框完整性前提（必须在执行日志中记录）**：三批工件须可读且行数不变
（aitester 261 行、`patch_plausible=1` 72 行）；若工件被清理或行数变化，须先按
`docs/design/repair_caliber_matrix.md` 的口径编号记录差异，再重跑抽样——**不得**用
不同批次的混合框凑数。

## 3. 评分量表（五选一，预注册固定）

判定集合（预注册原文，逐字）：`{equivalent（语义等价，应判 repair）, plausible_overfit,
wrong_location, test_only, incomplete}`。工作表每节的勾选栏即此五项
（`（工件已清除）` 表头"判定口径（预注册 E7
五选一）"）。

**逐条操作化定义**（来源标注；凡预注册未给出逐条判据者，本协议的操作化定义必须在
裁决开始前**冻结**）：

| 取值 | 操作化定义 | 来源 |
|------|------------|------|
| `equivalent` | 补丁与 gold `fixed` **语义等价**（差异仅注释 / 格式 / docstring 等无语义改动）——若成立应判 repair | 工作表表头判定规则 + 各节"判定提示"原文："仅有注释/格式/docstring 差异 → equivalent" |
| `test_only` | 补丁**改写测试而非源码**（未改动被测实现） | 工作表"判定提示"原文："改写测试而非源码 → test_only" |
| `wrong_location` | 改动**不在缺陷位置**（未触及缺陷所在逻辑） | 工作表"判定提示"原文："改动不在缺陷位置 → wrong_location" |
| `incomplete` | **未消除触发条件**（改动方向相关但不足以消除缺陷） | 工作表"判定提示"原文："未消除触发条件 → incomplete" |
| `plausible_overfit` | 补丁**看起来合理**（通过可行性证据门，即抽样框的 `patch_plausible=1`）但**未满足 gold 语义**——既非语义等价、也非上述三种结构形态 | **本协议操作化定义**（预注册只给类别名，未给逐条判据）：以"是否通过 `patch_plausible` 门"为"合理"的客观锚点，以"与 gold `fixed` 对照后无法归入 equivalent"为"未满足"的判据。**须在裁决前冻结并经两名裁决人确认理解一致** |

**判定次序（强制，减少歧义）**：先判结构形态（`test_only` → `wrong_location` →
`incomplete`，三者互斥优先），三者均不成立时再判 `equivalent` 与 `plausible_overfit`
（前者要求语义等价，后者为剩余桶）。裁决人若认为某行**无法归入**五类，须在备注中原样
记录，并计为**协议偏差**（不得临时新增类别；新增类别属量表修订，须回到预注册流程）。

**材料**：每行可用材料（工作表每节四段素材 + 机械 diff）为——生成补丁（patch）/
gold fixed（参考答案）/ gold 官方测试 / 最终生成测试（检出裁决者），以及 AQ1 增补的
`patch vs gold fixed` 逐行 `difflib` unified diff。口径提示（工作表表头原文）：整文件替换
口径下 **patch 正文即补丁应用后的完整文件**，与 gold `fixed` **逐行对照**即可分类；diff
段落是**机械对比**，判定仍属人工。

## 4. 双人独立裁决流程

1. **裁决人**：≥2 名，均须具备 Python 阅读能力；**互不沟通、互不可见对方判定**。
2. **独立性**：每人拿到**同一份工作表**的**独立副本**（各自填写"人工判定"列；
   建议文件名 `e7_review_worksheet_rater<A|B>.md`，但**不得**修改
   `（工件已清除）` 本体——它是备料工件）。
3. **盲法**：候选行来自 aitester 臂（单一臂），故**无臂盲**可言；能做的盲法是
   **先生成判定、后看聚合统计**——裁决人不得在完成全部行之前查看任何汇总指标
   （含漏斗分层占比、`patch_evidence_level` 分布）。
4. **顺序与时限**：按工作表候选编号顺序逐行判定；完成期限与工作量在
   `[待补充：裁决人名单与时间安排]` 中固定，**中途不得改量表**。
5. **记录**：每行记录 判定值 + 一句话理由（可选但建议，用于冲突解决时定位分歧来源）；
   若某行材料缺失（如 gold 材料不可读），记"不可判"并**不进 Kappa 的分母**，
   同时登记为材料缺口。
6. **汇总**：由**不参与判定**的第三方（或脚本）把两份副本合并为 5×5 混淆矩阵与
   原始一致率；合并前不得做任何"对表"。

## 5. 冲突解决

1. **分歧行的处理顺序**：①两裁决人**对表讨论**（仅针对分歧行，须在双方**原始判定
   已固化留痕之后**进行）；②达成一致的，记为**共识判定**；③仍不一致的，交**第三名
   裁决人**（未参与首轮）独立判定，以其判定为**终判**，并记录该行的三方取值；
   ④若第三名裁决人也无法归类（如材料不足），记"不可判"并进 §4 第 5 条的材料缺口清单。
2. **必须同时报告两套结果**：**首轮**（未讨论）的 Kappa 与一致率，以及**终判**后的
   标签分布；禁止只报讨论后的"更好看"数字（讨论会人为抬高一一致率，属已知偏置）。
3. **冲突率本身是结果**：分歧行数 / 总行数、被第三裁决人改判的行数，均须在报告中给出。
4. **不得因分歧修改量表**：若分歧集中在某一类（例如 `plausible_overfit` 与
   `incomplete` 的边界），正确做法是**在报告中披露该边界模糊**并（如需要）另立
   后续协议，而不是在执行中途重定义类别。

## 6. 信度统计量（唯一主口径：两名裁决人的 Cohen's Kappa）

**主统计量**：**未加权 Cohen's Kappa**（五分类为**名义**量表，类别间无公认序关系，
故不用加权 Kappa）。设 N = 两裁决人均作出有效判定的行数（"不可判"行不进分母），
`n_ij` = 裁决人 A 判为第 i 类、裁决人 B 判为第 j 类的行数，则：

```
p_o = (1/N) * Σ_i n_ii                      # 观察一致率
p_e = (1/N²) * Σ_i (n_i+ * n_+i)            # 期望一致率（行边际 × 列边际）
κ   = (p_o - p_e) / (1 - p_e)
```

其中 `n_i+` 为 A 的第 i 类行边际、`n_+i` 为 B 的第 i 类列边际。

**必须一并报告的项**：κ、`p_o`、`p_e`、N、5×5 混淆矩阵、两裁决人的类别边际分布、
讨论后改判行数、被第三裁决人改判行数。**κ 的 95% 置信区间**用 **bootstrap 百分位法**
（10,000 次重采样，固定 seed = 42——与 `experiments/statistical_analysis.py` 的
`_BOOTSTRAP_N_RESAMPLES = 10000` / `_BOOTSTRAP_SEED = 42` 同口径，保证可复现），
报告 CI 与重采样脚本（脚本须与结果同批入库）。

**解释带（Landis & Koch 1977 的通用约定，非本项目数据结论；引用时须标注为外部约定）**：

| κ 区间 | 解释 |
|--------|------|
| < 0.00 | Poor（差于随机） |
| 0.00 – 0.20 | Slight（轻微） |
| 0.21 – 0.40 | Fair（尚可） |
| 0.41 – 0.60 | Moderate（中等） |
| 0.61 – 0.80 | Substantial（显著） |
| 0.81 – 1.00 | Almost perfect（几乎完全一致） |

**预承诺（防止"看数换统计量"）**：

1. 主统计量固定为上述未加权 Cohen's κ；**不得**在看到结果后改用百分比一致率、
   加权 κ、Krippendorff's α 或 Gwet's AC1 作为主口径。
2. **流行度悖论（prevalence paradox）必须显式讨论**：若某一类占绝对多数（例如
   `wrong_location`），即使 `p_o` 很高，κ 也会被 `p_e` 抬高而压低——因此"κ 低"不等于
   "裁决人不可靠"，必须与 `p_o` 和边际分布同读。若确需敏感性分析，可**附加**报告
   Gwet's AC1，但须显式标注"**非预注册的次要分析**"。
3. **κ 的用途边界**：κ 只回答"该量表在两人间是否可复现"；它**不**回答"equivalent 占比
   是否为 0"。后者是 §1 的判定问题，须用终判标签分布（含"不可判"计数）单独报告。
4. **若 κ 落在 Fair 及以下**：结论必须写成"裁决口径不足以支撑定量结论"，并把
   `equivalent` 占比作为**定性线索**报告（或按 §2.1 路径 B 放大样本后重做），
   不得据此更新 BASELINE / pooled 报告。
5. **超过两名裁决人时**：主口径仍是**指定的两名独立裁决人之间的 Cohen's κ**
   （预注册要求双人独立）；其余参与者两两之间的 Cohen's κ 可作为附加项，
   全组一致性可用 Fleiss' κ 作附加项，均须标注为次要分析。
