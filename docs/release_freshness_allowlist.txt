# 发布新鲜度例外登记（`scripts/gates/check_release_freshness.py`）
#
# 语法：`<tag 名>  # 理由`
# 语义：最新 release tag **落后于默认分支**时，若该 tag 在本表登记 ⇒ 绿（显式承担），
#       但门禁仍会打印落后了多少个提交；未登记 ⇒ 红。
#       本表的某条若**不再对应当前最新 tag** ⇒ 记「例外已失效」⇒ 红（tag 前移后必须清理）。
#
# 例外必须写理由；「因为来不及」不是理由。理由写**一行**（续行会被当作注释丢掉）。
#
# EZ 轮（2026-10-27）：`v1.0.0` 已前移到 main 的 HEAD（作者明确同意 force-update 已发布引用），
# 原有例外条目随之失效并删除——本表现为空表（空表 = 没有需要承担的落后，不是「未判定」）。
#
# EB 轮（2026-10-27）：上面两条语法承诺在**每次运行**都判，且在任何绿色 / 跳过之前——
# tag == HEAD、最新 tag 已登记、仓库没有 `v*` tag 都**不**豁免；无理由是本地缺陷，
# 不依赖 GitHub API 是否可达。登记≠通行：失效条目留在表里会让门禁红。
