**轮次性质**：工程质量轮（AB 轮）第 1 项。零 LLM 调用、真实花费 **$0**。
不改任何被评估代码的行为，只把一条"合成枚举得出的结论"换成"真实语料得出的结论"，
并在此过程中**否证了原结论的推理前提**。

## 1. 问题

`src/utils/helpers.py` 的 JSON 提取降级链里，**档 2**（首对象修复档，
调用点 `helpers.py:791`、返回分支 `helpers.py:802-803`）的返回分支在 AA-5 被判为"恒不可达"。当时的依据是：

> 档 1 与本档在同一首 `{` 上取片段（候选集相同，档 1 已全失败），
> 仅"字符串外裸反斜杠"会让两个扫描器分歧，而分歧片段本身含非法转义、
> 五个候选无一救活（54,006 输入枚举，0 例）。

这句话有两处弱点：**"恒不可达"是全称命题**，依据却是**合成残片枚举**。
ROUND4 审计据此把"用真实语料重算"列为下一轮项。盘上恰好有语料——产品自身的
LLM 响应缓存存的是**原始响应字符串**，可直接喂给 `extract_json_object` 复算。

## 2. 口径（先把"走到档 2"定义清楚）

`extract_json_object` 只在档 2 入口调用一次 `_first_balanced_object`
（`src/utils/helpers.py` 全文仅 1 个调用点，重放脚本用 `tier2_multi_call` 计数器
持续守这个假设，本次实测为 **0**）。据此把四层**分开**计数，而不是合成一个数：

| 层 | 含义 |
| --- | --- |
| `tier2_entered` | 该响应的解析过程**到达**了档 2 调用点 |
| `tier2_no_fragment` | 到达档 2 但扫描器取不到片段 |
| `tier2_fragment` | 取到了片段（五个候选随之后） |
| `tier2_would_return_nonempty` | 五个候选里有**非空字典**可解析 ⇒ 返回分支真会触发 |

再补一层**机制**口径：档 2 相对档 1 的唯一增量只在"两个扫描器分歧"时才存在，
故单独统计 `tier2_scanner_divergent` 与其子集 `divergent_would_return_any`。
**"总数 0"说明冗余，"分歧子集 0"才说明为什么冗余。**

## 3. 结果（语料 = 7,565 条真实响应，文件名清单 sha256 `257799ac37a8627a…`）

| 指标 | 值 |
| --- | --- |
| 使用的响应条数 | **7,565**（目录内 JSON 7,565，无坏文件） |
| 直接解析成字典 / 抛错 | 4,756 / 2,809 |
| 走到叶子回退档 | 407 |
| Planner 形态响应（system 含 `logic_analysis`） | 1,534 |
| 含 ≥2 个 `{` 的响应 | **5,014** |
| 到达档 2 | **692** |
| 档 2 取不到片段 | 25 |
| 档 2 取到片段 | **667** |
| 两个扫描器分歧 | **1** |
| 档 2 返回分支**真会触发** | **0** |
| 分歧子集里会触发 | **0** |
| 一次响应多次进入档 2 | 0 |

两次独立实现（临时脚本 / 本仓固化脚本）逐条对上：692 到达、667 取到片段、
5,014 多对象形态、407 叶子回退、25 取不到片段、**0** 次返回。
同输入两次运行输出逐字节相同。

**第三条独立证据（口径不同）**：AA 轮收口的 `coverage.xml` 里，
`utils/helpers.py` 的未覆盖行包含**档 2 返回分支那两行**
（当时编号 786/787，即 `if isinstance(_obj, dict) and _obj:` 与其 `return _obj`；
AB-1 改注释后为 800/801，**AB-6 收口按最新 `coverage.xml` 复核为 802/803**——这两行号随
上方注释与 docstring 的增删漂移，引用时以 `grep -n "isinstance(_obj, dict) and _obj" src/utils/helpers.py`
现算为准）。语料重放说"真实输入不触发"，覆盖率说"9,485 例测试
也不触发"——两个口径互不依赖，指向同一结论。

## 4. 结论一：观测结论成立，但**原推理前提是错的**

"返回分支 0 次触发"在真实语料上**复现**（0/667）。但 AA-5 给出的理由——
"档 1 与本档在同一首 `{` 上取到**同一个**片段，候选集相同，故档 1 已经全试过"——
在那 **1 条分歧样本**上**不成立**：

- 该响应 5,319 字符、以 `{` 开头、无代码围栏；
- `_find_balanced_json`（档 1）对它的返回值是 **`None`**，不是"不同片段"——
  即**整个档 1 修复块被跳过**；
- `_first_balanced_object`（档 2）取到 2,089 字符、括号 30/30 平衡的片段。

⇒ 在这一类输入上，**档 2 是第一个、也是唯一产出候选片段并做语法修复的档**，
它不是档 1 的重复。它这次没返回是因为那 5 个候选救不活这个片段
（原始错误 `Expecting ',' delimiter`，位于片段 1,421 字符处——属 D1 记过的
"值位置写 Python 表达式"类），**不是因为档 1 已经先试过**。

## 5. 结论二：分歧机制已定位，且"救不活"是结构性的

两个扫描器都是"字符串感知的括号深度"扫描器，但**转义口径不同**：

- `_find_balanced_delimited`（`helpers.py:488`，经 `_find_balanced_json` 调用）
  在**字符串外**也把 `\` 当转义符——置 `escape` 后**吃掉下一个字符**；
- `_first_balanced_object`（`helpers.py:170`）在字符串外**忽略** `\`。

后果：片段里一个串外 `\` 紧跟 `}`，档 1 把这个 `}` 当被转义内容、深度不归零，
扫到文末返回 `None`；档 2 正常在同一个 `}` 处返回完整片段。
那 1 条语料样本实测**只有 1 个串外反斜杠**（片段内位置 1,495），正是此形。

最小复现（已钉进回归锁）：

```
'{"a":\\}{"b":1}'   →  档 1 None / 档 2 '{"a":\\}'
```

**为什么这类片段必然救不活**：分歧成立的前提，就是档 2 返回的片段里**含有**
那个字符串外的裸 `\`（否则两个扫描器状态不会错开）；而 JSON 语法在字符串外
不允许裸反斜杠，档 2 的 5 个候选（原文 / 尾随逗号与字面量修复 / Python 表达式
加引号 / 二者复合 / 有界迭代）**没有一个以删除反斜杠为手段**，故 5 个候选全失败。
这条不是"只看了 7,565 条没抓到"的经验结论，而是有机制支撑的——
定向枚举分歧类输入 **716 例，档 2 可返回 0 例**（同一断言已钉成
`TestDivergentClassUnrescuable`，并验证"若将来加入删反斜杠的候选，该锁立刻转红"）。

## 6. 处置：档 2 **保留**，理由与措辞都换了

| | AA-5 的说法 | AB-1 之后 |
| --- | --- | --- |
| 返回分支 | **恒不可达**（全称命题，依据=同片段合成枚举） | **0 次触发**：7,565 条真实语料 0/667、分歧类定向枚举 0/716、覆盖率 0 行命中——三口径一致 |
| 论证 | "档 1 与本档取到同一片段，已全试过" | **该前提被否证**（存在档 1 返回 `None` 的真实分歧样本）；改由机制论证支撑：分歧片段必含串外裸 `\`，而 5 个候选都不删 `\` |
| 本档地位 | 档 1 的重复 | 在分歧类里是**首个也是唯一**产出片段并做修复的档——**尝试**不重复，**返回**没发生过 |
| 删除的影响 | "属行为变更需单独轮次" | 现有全部证据下**不改变返回值**（`TestDeletionEquivalenceProbe` 在 4 类钉住输入上"有档 2 / 无档 2"输出逐字相同），只省掉 5 次注定失败的解析尝试 |

**决定不变、依据变**：仍**不删除**。不是因为它会返回，而是因为
①"不改变返回值"目前是三条经验证据的合致，不是证明；
②删除属行为变更，按既定纪律要单独一轮，且必须带着 AB-2 的等价性锁去做——
那把锁现在就是"真删的时候会不会出问题"的探针：将来任何让分歧片段变得可救的
改动（例如新增删反斜杠的候选），会先让
`TestDivergentClassUnrescuable` 转红，而不是等到删完之后才发现语义漂了。

`helpers.py` 注释已同步：删掉"恒不可达"这个全称措辞与"档 1 已全失败"这个错前提。

## 8. 隐私纪律（本轮踩到并已修的一处）

缓存含完整 prompt 与响应正文（可能夹带被测代码）。脚本自身只打印聚合计数，
但**被观测的 `helpers` 在叶子回退档会 `logger.warning` 打印片段前缀**
（`helpers.py:835`/`847`——AB-6 收口按当前源码复核已漂移为 `837`/`849`，行号请以
`grep -n "logger.warning" src/utils/helpers.py` 现算为准）——那不是脚本在打印正文，却让"输出只是聚合数"这句
话变成假的：首版重放 7,565 条时 stderr 被 2,793 条含正文前缀的告警刷屏。

处置：重放期给 `helpers` 的 logger 挂**只计数不放行**的 filter，把正文型告警
换算成 `n_suppressed_warnings`（本次实测 2,793）。信息一条不少（条数保留），
正文一条不出。回归锁同时断言"输出中无哨兵串"**且**"抑制计数 > 0"——
只断言前者会退化成空锁（告警压根没触发时也会通过）。
