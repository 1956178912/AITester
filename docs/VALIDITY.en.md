## 0. Purpose, evidence discipline, and status definitions

This document answers the question reviewers are most likely to ask: **within what
range do these conclusions hold, and where do they not**. The reporting caliber matches
the project's existing honesty discipline — main-batch numbers have `BASELINE.yaml`'s
`benchmark` section as the single source of truth (benchmark-metrics row of `README.md`)
— but this document cites only artifacts and decision records that can be opened and
re-checked directly, never second-hand paraphrase.

Three rules apply throughout:

1. **Mandatory caliber labels**: any repair / false_fix / detection number must carry a
   caliber label (`docs/design/repair_caliber_matrix.md` §3 "citation discipline": repair
   calibers are ①–⑨, false_fix calibers ⑩⑪ live in that file's "false_fix caliber
   (authoritative landing point)" section);
2. **Commit policy for derived artifacts**: machine-regenerable derivatives default to
   staying out of version control, with the evidence chain pointing at their source
   artifacts (`docs/emse/EMSE_OPTIMIZATION_2026-10-15.md` §5); allow-listed `main_batch/`
   statistical reports travel with the evidence chain (e.g. `mutation_detection_correlation.md`,
   committed as of the 2026-10-16 batch), while `emse_swebench_disclosure.md` remains
   uncommitted;
3. **No human adjudication anywhere**: project-wide, "gold independent adjudication"
   always means an automated oracle whose *adjudicating material* is independent
   (held-out gold tests / gold patches), **never human adjudication**; the E7 human
   review is preregistered but **has not been executed**, and no Kappa artifact exists
   anywhere (benchmark-metrics row of `README.md`; verification in §7 item 1).

## 5. Item-by-item disposition of OPEN threats (unmitigated reason → mitigating experiment → paper scoping)

### 5.1 `detection_rate` as a proxy for "test quality" (construct validity, open)

- **Why it is unmitigated**: the only external calibration signal for "quality" available on this dataset — the mutation score — is **saturated**: the authoritative artifact `experiments/results/main_batch/mutation_detection_correlation.md` aggregates **all 10** batch JSONs under `experiments/results/main_batch/` (paired n 556 / 609 / 571) with stratified means of 0.87–1.00; the stratified direction for `plain_llm_df` is even negative (Δmean = −0.0098, labelled "no discriminative power (saturated)"), while `aitester` and `plain_llm` are only weakly positive (Δmean = +0.1263 / +0.0232) (same file, rows 15–17). **Caliber note**: the "R-P0-2 three-seed, n=261/arm" table previously cited in `docs/emse/EMSE_OPTIMIZATION_2026-10-15.md` §2 (Δmean = +0.0456 / +0.0290 / −0.0036) was **explicitly superseded and deleted** by that file's 2026-10-15 caliber note — the two tables cover different populations (10 batch files vs three seeds), and this document cites only the former, authoritative artifact. A saturated metric cannot serve as a calibration criterion, so the "proxy" claim lacks usable convergent evidence.
- **What would mitigate it**: pair detection with a **non-saturated** external signal — the ULT full-mutant Mut@k (sound-subset caliber, `docs/design/repair_caliber_matrix.md` row ⑨) already has a recompute entry point, but that subset also carries a validity gap (generated-suite pass rate on the target code 19.6%/20%, `docs/emse/EMSE_SUBMISSION_CHECKLIST_2026-10-15.md` §4 item 10) and a void gold reference (same checklist §4 item 11); the feasible next step is the E7 human review establishing a **human calibration criterion** for detection (`docs/emse/EMSE_OPTIMIZATION_2026-10-15.md` §3 records it as "the only action that can establish an external calibration criterion for detection").
- **How the paper must scope its conclusions if this stays open**: detection may **only** be described as "a detection signal on this benchmark (protocol-level signal)" and never as a general proxy for test quality; the mutation-correlation numbers must be disclosed as **counter-evidence on construct validity**, together with the report's "interpretation discipline" (never cited alone; always read alongside the stratified means) (`experiments/results/main_batch/mutation_detection_correlation.md` lines 8–11; `docs/emse/EMSE_OPTIMIZATION_2026-10-15.md` §2 conclusion 3).

### 5.2 Cross-arm false-fix comparison confounded by the pass-declaration rate (construct validity, open)

- **Why it is unmitigated**: the **conditional** false-fix rate is 100% for all three arms (recomputed here: 143/143, 229/229, 7/7; the T-10 report §2 gives the same values with Wilson CIs 100% [97.38, 100] / [98.35, 100] / [64.57, 100]), and all the variation lives in the share of "success" declarations in the marginal denominator (54.79% / 87.74% / 2.68%, `experiments/results/emse_stats_2026-10-15/PASS_MATCHED.md` §1). `plain_llm_df` has only 7 passed rows, so any "conditional on passed" cross-arm comparison has no power at all. The T-10 verdict is that **all** of the marginal false-fix difference comes from the success-declaration rate and that the two are "**inseparable in this design**" (same report §5 item 1), so the report **directly refutes** the causal reading "the detection-first protocol reduces false fixes" (same report §1 key observation and §5 item 2).
- **What would mitigate it**: T-10 already delivers a **descriptive** mitigation (success-declaration rate as a first-class endpoint + conditional caliber + a template-matched subset: **strict caliber** key = pattern×difficulty×seed, **29 rows / 25 measurable** with **0** detections (0.00%), against its complement 232 rows / **215 measurable** with 38 detections (17.67%); **loose caliber** key = pattern only, **62 rows / 55 measurable** with **0** detections (0.00%), against its complement 199 rows / **185 measurable** with 38 detections (20.54%); **strict and loose are different populations, not complementary counterparts**, so the two groups must not be pieced into one 2×2 table; same report §3); but the report itself says that "a 2×2 ablation (protocol-text switch × regeneration budget) is needed to separate the 'text effect' from the 'behaviour effect'; this report does not replace that experiment" (same report §5 item 4), i.e. the ablation in §5.5 is the definitive route.
- **How the paper must scope its conclusions if this stays open**: it must **not** claim that the detection-first protocol or the full system is better at "false fixes"; it may only report the two facts — the declaration rate and the conditional false-fix of 100% — and explicitly attribute the marginal false-fix differences to the declaration-rate difference. The false_fix citation discipline in the `README.md` (caliber tags mandatory) is **necessary but not sufficient**; the authoritative caliber landing point is the "false_fix caliber (authoritative landing point)" section of `docs/design/repair_caliber_matrix.md` (⑩⑪).

### 5.3 LLM version drift + temperature caliber (internal validity, open)

- **Why it is unmitigated**: the main batch ran before the fingerprint feature existed: provenance has no `model_fingerprint` key and `git_dirty=true` (all three JSONs verified here), and the model is the floating alias `deepseek-flash`; drift **has already been observed** (same tasks and seeds, `plain_llm` detection 1.5%→19.2%, `scripts/gates/check_model_fingerprint.py` docstring), and the gate does not defend historical batches by design (default: last 2 days only). The fingerprint feature has landed for batches from 2026-10-13/14 onward (see §2), but it **cannot be back-filled** into the main batch — the gap is confined to results from 2026-10-06 and earlier.
- **What would mitigate it**: re-run the main batch under the fingerprint gate (`pinned=true`) and report the old-vs-new difference as an "alias drift sensitivity" analysis; until then any confirmatory claim should be treated as non-reproducible. The in-repo alternative is the report JSON's `env_snapshot` (switches and temperature) plus `git_sha`, but `git_dirty=true` means the sha alone cannot reproduce the code state (`experiments/results/main_batch/statistical_report_3seed_pooled.md`, AK erratum 1).
- **How the paper must scope its conclusions if this stays open**: describe main-batch results as a **snapshot of a floating alias within a specific time window**; avoid any "reproducible across runs" wording; the fact that "pin seed/model/temperature/dataset-version in the reproduction package" is not executed (`docs/emse/EMSE_OPTIMIZATION_2026-10-15.md` §3) belongs in Limitations.

### 5.4 Cross-language generalization (external validity, open)

- **Why it is unmitigated**: there is **no** Java (or other non-Python) experiment in the repository; only a design document (`docs/design/multilanguage_extension.md`) and an unchecked TODO (`docs/failure_analysis.md`). The Java directories shipped by upstream QuixBugs are not consumed by the loader (`docs/DATA_CARD.md` §1 records "QuixBugs (Python subset, complete 50 programs)"; `docs/emse/EMSE_QUIXBUGS_SPECIR_EXPAND_PREREG_2026-10-14.md` §7 records "QuixBugs local is the complete Python subset (50 programs)").
- **What would mitigate it**: implement a non-Python dataset adapter and run an L1 smoke test (minimal judgeability check), or fill the toolchain gaps listed in `docs/design/multilanguage_extension.md` and run Defects4J; a low-cost alternative is to **state the non-claim explicitly** and put cross-language work in future work (an honest downgrade beats a rushed extrapolation).

### 5.5 The causal claim "detection-first → fewer false fixes" (conclusion validity, **reduced** — T round 2026-10-18 fingerprint-grade three-cell × 2-seed replication)

- **Why it is unmitigated**: the intervention is a **protocol package**, not a single variable — `DETECTION_FIRST_ENABLE` simultaneously changes the routing (all-green first round → regenerate), the regeneration accounting, and the prompt section (`_detection_first_regenerate_entry` and the reinforcement-section builder in `src/graph/nodes.py`; `docs/adr/0015-detection-first-protocol.md` decisions 2–4; T round onward locates by function name instead of drift-prone line numbers).
